# 铺市运行契约

本文件只定义执行协议：状态链、门禁和完成口径。业务方法在 `skills/` 里，身份与姿态在 `SOUL.md` 里。本文件保持机械、严格、不可绕过。

## 唯一入口

一次铺市任务就是一次 run。Agent 只能通过下列工具推进 run，不能直接读写 run 目录，也不能绕过检查写产物：

| 工具 | 作用 |
|---|---|
| `status` | 读取当前进度：已完成的关卡、下一关、各关结论摘要、回退次数、能否收尾 |
| `load_skill` | 读取一份业务技能（判断方法、证据要求、自查清单） |
| `run_stage` | 执行下一关：代码准备数据与计算，模型按该关技能做判断，代码检查；未通过时自动带着问题重试，最多 3 次 |
| `backtrack` | 回退到一个已完成的关卡，让它和之后的关卡重做 |
| `ask_user` | 向客户提一个会实质改变结果的问题，本轮停下等待回复 |
| `finish` | 收尾：生成作战包文件，把 run 标为完成 |

## 状态链

```text
立项 L0 → 卖给谁 L1 → 找终端 L1D → 去哪里 L2 → 对手 L2C → 进哪家 L3 → 供货 L3P → 怎么说 L4 → 作战包 PACK → finish
```

## 强制门禁

1. 只能运行状态链上的下一关；已完成的关卡要重做必须先 `backtrack`。
2. 每关产物都由代码检查：结构、引用（商户、卖点、上游结论可追溯）、业务规则（用户硬约束、计算复算、合规扫描）。未通过的产物不进入下游。
3. 检查不得放宽。`run_stage` 三次仍未通过时，该关保持未完成；Agent 只能改写指引重跑、回退，或用 `ask_user` 说明缺什么。
4. 「进哪家」发现选中网格的 A/B 门店不足时，代码自动排除这些网格并回退到「去哪里」，阈值不降低；回退有次数上限。
5. `backtrack` 每个 run 最多 3 次（不含第 4 条的自动回退）。
6. 立项缺少会改变结果的信息（位置、半径、产品）时，先 `ask_user`，不猜。

## 完成口径

只有以下条件全部满足，才允许说任务完成：

```text
九关全部通过检查
finish 调用成功
run status = completed
首访名单 CSV 已生成
```

以下都不等于完成：某一关的结论、模型给出的总结、部分关卡通过、run 仍在运行或已停下。
