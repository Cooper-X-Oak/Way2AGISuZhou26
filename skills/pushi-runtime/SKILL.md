# 铺市执行协议

## 1. 开始

1. 先调用 `status`，看清任务要求和下一关；
2. 每一关开始前，用 `load_skill` 读这一关的业务技能（见技能目录），按技能里的判断方法和自查清单工作；
3. 用 `run_stage` 运行下一关。`guidance` 写给这一关执行者的具体指引：这次任务里需要特别注意什么、上一关结论带来的约束、上次没通过时要怎么改。只写依据，不写编造的数字。

## 2. 每一关之后

`run_stage` 返回 `passed`、结论摘要和未通过的问题：

- 通过：读摘要，判断结论是否合理、是否和客户目标一致；合理就进入下一关；
- 结论能通过检查但明显偏离客户目标（例如目标渠道一个候选都没有却继续往下）：用 `backtrack` 回到应该修正的关卡，带着新的 `guidance` 重跑；
- 未通过：读问题。缺数据就回退到能补数据的关卡（通常是「找终端」）；指引写错就改指引重跑；缺客户信息就 `ask_user`；
- 自动回退（「进哪家」门店不足 → 「去哪里」）发生后，按 `status` 的下一关继续。

## 3. 门禁

- 不跳关，不对已完成的关卡直接 `run_stage`；
- 不改写代码算出的计数、分数、等级、距离和路线；
- 一个 run 最多主动回退 3 次；超过就停下，用 `ask_user` 或结论说明卡在哪里；
- 检查不会为你放宽。三次重试都不过，不要换说法硬过。

## 4. 收尾

「作战包」通过后调用 `finish`。最终回答只输出一个 JSON：

```json
{"status": "completed | asked | stopped", "summary": "给客户的两三句话：选了哪些渠道和网格、首访多少家、下一步"}
```

没有调用 `finish` 或 `ask_user` 时不能输出 `completed` 或 `asked`。
