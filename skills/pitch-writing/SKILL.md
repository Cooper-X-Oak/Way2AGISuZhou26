# 怎么说（进店话术）

打磨话术改这一份文件。程序检查写在 `pipeline/workflows/pitch/review.py`，不会因为本文件的改动而放宽。

## 1. 先整理资料

- 用 `list_targets` 读取全部必写目标。每个目标带有：渠道、所在网格的切入策略和规定的切入角度原句、可引用的卖点原文、门店资料（名称、类型、分级理由、首访动作）、未知项，有时还有档案提供的渠道参考写法；
- 区分两种目标：
  - **门店**：有商户资料，可以写这家店为什么值得拜访；
  - **渠道兜底**：选中网格里没有这个渠道的 A/B 门店，只有渠道资料。写成通用版，不能假装研究过某家店；
- 只把有出处的信息当事实。客群、需求、采购偏好没有证据时，写成到店要问的问题；
- 当前只整理已有资料，没有搜索网页，不要声称查过网页或评价。

## 2. 写法

按这个顺序组织成自然的口语：

1. **开场**：说明来意，找对人（店长、茶席或行政负责人、场馆运营等）；
2. **与这家店相关的切入点**：从门店类型、分级理由或渠道场景出发，说明为什么找它；
3. **需求问题**：把未知项变成现场能问的问题，例如现在怎么安排用水、谁负责采购；
4. **产品事实**：卖点逐字引用原文，不改写、不扩写成功效；
5. **下一步**：给出具体可执行的动作，例如样品、品饮、核对设备，并说明进货成本和售价需要和老板确认。

另外还要做到：
- 必须逐字包含规定的切入角度原句。策略是「避让」时，先做需求访谈，不推动替换现有方案；
- 档案提供的渠道参考写法可以借鉴语气和结构，但这家店的切入点和问题要自己写；
- 不同产品按各自档案来写，不要把所有产品都默认成饮用水；
- 桌牌只写一句，不出现价格和承诺。

## 3. 边界

- 不写价格、毛利、折扣、买赠、首单政策、保底利润或保证销量；
- 不写功效宣称，不点名或贬低竞品；
- 商户名称和品类只能来自资料，不能只替换店名就当作个性化；
- 合规结果由代码扫描生成，不能自己声明「已合规」。

## 4. 自查与完成标准

- 每写一条都用 `check_pitch` 自查，没通过就按提示改，改完再查；
- 每个必写目标恰好一条；整批交稿时程序会再检查一次，有遗漏会被打回；
- 程序检查通过只说明满足了来源、覆盖、合规和商业承诺这些约束，不代表业务效果已经验证。人工打磨时重点看三件事：有没有讲清为什么找这家店、问题问得对不对、下一步是不是具体。
