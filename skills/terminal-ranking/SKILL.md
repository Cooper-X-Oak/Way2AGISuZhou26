# 进哪家（门店分级）

## 当前版本的分工（如实说明）
- 分数、A/B/C 等级和首访动作由代码按距离、渠道优先级等明确公式计算；
- 每家门店的理由只能使用代码给出的 allowed_reason 原文。这同样是「等于规则答案」式的检查，是已知限制。后续版本要允许模型结合门店信息写出依据，代码只校验商户存在、引用可追溯和计算正确。

## 你仍然要做的
- 在 decision 里说明首访名单是否符合客户目标（例如主攻渠道是否进入 A/B）；
- 如果 A/B 门店明显偏离客户目标，在 Agent 层考虑回退到「找终端」补采或回到「去哪里」。

## 边界
- 不改写分数和等级；只引用候选里真实存在的商户。
